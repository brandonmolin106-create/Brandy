# 04 · Devlog and content (12 prompts)

### 4.1 Devlog post
```
Act as an indie developer who writes well. Write a 500-word devlog post about [topic] for {{PRODUCT}}, voice {{VOICE}}. Structure: the problem in the first two sentences, what I tried, what worked (with one concrete detail or number), what I'd do differently, and a soft close with the store or wishlist link. No "excited to announce". Title in under 9 words.
```

### 4.2 Build-in-public update
```
Act as a build-in-public writer. From these notes: [paste], write a 120-word progress update for X or LinkedIn: one win, one struggle, one number, one question to the audience. No hashtags in the body; suggest 3 at the end.
```

### 4.3 Newsletter issue
```
Act as a newsletter editor. Write issue [n] of my newsletter for {{AUDIENCE}} about {{PRODUCT}}: subject line (under 45 chars) + preview text, a 90-word opener that gives value before mentioning the product, a 3-item middle (tip, behind the scenes, link), and a one-line CTA. Total under 350 words.
```

### 4.4 "How I made it" post
```
Act as a technical writer for a general audience. Write an 800-word "how I made {{PRODUCT}}" post: the tools, the one hard problem and how it was solved (with a snippet or diagram description), the numbers (time, size, count), and what the reader can steal for their own project. End with the link.
```

### 4.5 Content calendar, 4 weeks
```
Act as a content strategist. Build a 4-week content calendar for {{PRODUCT}} across X, one devlog platform, and email: 3 X posts a week, 1 devlog a week, 1 email every 2 weeks. Each slot: topic, format, hook line, asset needed. Weeks 1–2 pre-launch, 3 launch, 4 post-launch.
```

### 4.6 Repurpose one post into five
```
Act as a content repurposer. I'll paste one devlog post. Turn it into: an X thread (5 posts), a 60-second video script, a Reddit post with a non-promotional title, a LinkedIn post, and 3 newsletter bullets. Keep facts identical across all five.
```

### 4.7 Devlog titles
```
Act as an editor. Write 15 devlog titles for {{PRODUCT}} that a stranger would click: specific, with a number or a tension, under 9 words, no clickbait that the post can't pay off. Group by theme: process, problem solved, numbers, opinion.
```

### 4.8 Tutorial post
```
Act as a tutorial writer. Write a step-by-step tutorial that uses {{PRODUCT}} to accomplish [task] for {{AUDIENCE}}: prerequisites, 6–10 numbered steps with the expected result after each, one troubleshooting block, and a closing "what to try next". Under 900 words.
```

### 4.9 Behind-the-numbers post
```
Act as a transparent founder. From these figures: [paste], write a 400-word "numbers" post: what was spent (time, money), what came in, the surprising ratio, the lesson, and the one thing I'll change. Include a small plain-text table.
```

### 4.10 Comparison post (fair)
```
Act as an honest reviewer. Write a 600-word comparison of {{PRODUCT}} against the two most common alternatives for {{AUDIENCE}}, with a table (price, what's included, licence, best for). Say plainly where each alternative wins. End with who should not buy {{PRODUCT}}.
```

### 4.11 Changelog to story
```
Act as a release-notes writer. Turn this changelog: [paste] into update notes people enjoy reading: a 2-sentence headline on the biggest change, grouped bullets (new, improved, fixed) in user language, and one line on what's next. Under 250 words.
```

### 4.12 Devlog critique
```
Act as a blunt editor. I'll paste a devlog draft. Cut every sentence that doesn't teach, show or move the story. Flag jargon. Suggest a stronger first line and a stronger last line. Return the edited version and a word count before/after.
```
